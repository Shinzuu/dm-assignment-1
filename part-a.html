Problem 3.4

Suppose that a data warehouse consists of the

three dimensions time, doctor, and patient, and

the two measures count and charge, where charge

is the fee that a doctor charges a patient

for a visit.

(a) Enumerate three classes of schemas that are

popularly used for modeling data warehouses.

Answer: The three schema classes are:

1. Star schema. One central fact table holds the

measures and one foreign key per dimension.

Each dimension is a single table.

2. Snowflake schema. A star schema in which some

dimension tables are normalised into smaller

tables, giving a snowflake shape.

3. Fact constellation, also called a galaxy

schema. Several fact tables share the same

dimension tables.

(b) Draw a schema diagram for the above data

warehouse using one of the schema classes

listed in (a).

Answer: A star schema. The fact table fee holds

the measures count and charge and one key for

each of the three dimensions.

(c) Starting with the base cuboid [day, doctor,

patient], what specific OLAP operations should

be performed in order to list the total fee

collected by each doctor in 2010?

Answer: Three operations, in this order:

1. Roll-up on time from day to year, so

each cell sums the charge of a whole year.

2. Slice on time with year = 2010.

3. Roll-up on patient from individual patient to

all, so the charge is summed over

every patient.

The result is the cuboid [2010, doctor, all]. Each

cell holds sum(charge), the total fee collected by

one doctor in 2010.

Problem 3.5

Suppose that a data warehouse for

Big_University consists of the four dimensions

student, course, semester, and instructor, and

two measures count and avg_grade. At the lowest

conceptual level (e.g., for a given student,

course, semester, and instructor combination),

the avg_grade measure stores the actual course

grade of the student. At higher conceptual

levels, avg_grade stores the average grade for

the given combination.

(a) Draw a snowflake schema diagram for the

data warehouse.

Answer: The fact table university holds count and

avg_grade. Student, course and instructor are

normalised: student points to major, and course

and instructor both point to department.

Problem 3.53 / 21

(b) Starting with the base cuboid [student,

course, semester, instructor], what specific

OLAP operations (e.g., roll-up from semester to

year) should you perform in order to list the

average grade of CS courses for each

Big_University student.

Answer: Four operations, in this order:

1. Roll-up on course from course_id

to department.

2. Roll-up on semester to all, and on instructor

to all.

3. Dice on department = "CS" and university

= "Big_University".

4. Keep student at the student level, so there

is one row per student.

The result is [student, CS, all, all], holding the

average CS grade of each Big_University student.

avg_grade is an algebraic measure. To roll it up,

keep sum(grade) and count, then divide. An average

of averages gives a wrong answer.

(c) If each dimension has five levels

(including all), such as "student < major <

status < university < all," how many cuboids

will this cube contain (including the base and

apex cuboids)?

Answer: Each dimension can be taken at any one of

its five levels, so the number of cuboids is

the product of the level counts:

cuboids = 5 x 5 x 5 x 5 = 5^4 = 625

The cube contains 625 cuboids. This count already

includes the base cuboid and the apex cuboid.

Answer: Four operations, in this order:

Problem 4.6 (a)9 / 21

Comparing the efficiency

1. Apriori scanned the database three times,

once per itemset size. FP-growth scanned

it twice.

2. Apriori generated 10 candidate pairs and 4

candidate triples, and 8 of these 14 were not

frequent. FP-growth generates no candidates.

3. FP-growth mines the compact tree in memory,

by building smaller conditional trees. It is

the more efficient of the two.

Problem 8.17

Describe each of the following clustering

algorithms in terms of the following criteria:

(1) shapes of clusters that can be determined;

(2) input parameters that must be specified;

and (3) limitations.

(a) k-means

Answer: (1) Shapes: spherical, convex clusters of

similar size.

(2) Input: k, the number of clusters.

(3) Limitations: k must be given in advance. The

result depends on the initial centres and can be

a local optimum. Outliers pull the mean away. It

needs numeric data, because it computes a mean. It

cannot find non-convex clusters.

(b) k-medoids

Answer: (1) Shapes: spherical, convex clusters,

the same as k-means.

(2) Input: k, the number of clusters.

Problem 8.1720 / 21

(3) Limitations: k must be given in advance. Each

iteration of PAM costs O(k(n-k)^2), so it does not

scale to large data. It still fails on non-convex

shapes. It is more robust to outliers than

k-means, because a medoid is a real object.

(c) BIRCH

Answer: (1) Shapes: spherical. A CF-tree

summarises each subcluster by its radius or

diameter, which suits round clusters.

(2) Input: the branching factor B and the

threshold T of the CF-tree, and k if a

global clustering step follows.

(3) Limitations: numeric data only. The result

depends on the order the data arrives in and

on the choice of T. It handles non-spherical

clusters poorly.

(d) DBSCAN

Answer: (1) Shapes: arbitrary. Any

density-connected region becomes a cluster, and

sparse points are marked as noise.

(2) Input: Eps, the neighbourhood radius, and

MinPts, the least number of points that makes a

core point. The number of clusters is not needed.

(3) Limitations: one global Eps and MinPts cannot

fit clusters of very different density. The result

is sensitive to both values. Distances lose

meaning in high dimensions. Without a spatial

index it costs O(n^2).
